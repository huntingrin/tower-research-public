# 分析 Playbook

检索解决“有什么”，分析解决“这意味着什么、下一步做什么”。

---

## 1. 选视角

从 prompt 判断，默认“客户历史 + 商机状态”。

| 视角 | 适用问题 | 核心输出 |
|---|---|---|
| 客户历史 | “这个客户聊到哪一步了” | 时间线、对接人、阶段 |
| 商机复盘 | “为什么没成/卡在哪” | 预算、决策链、卡点、竞品 |
| 承诺追踪 | “谁答应了什么” | 承诺、截止、兑现状态 |
| 代理情报 | “代理在推什么” | 代理名单、客户盘、预算偏好 |
| 人物地图 | “谁说了算” | 角色、关系、影响力 |
| 内容资产 | “我们做过什么” | 方案版本、报价、案例 |

可以叠加，不要超过 2 个主视角。

---

## 2. 单帖分析

每篇直接相关帖子至少回答：

1. 这是什么（背景）
2. 谁参与（角色）
3. 客户要什么（需求）
4. 我们提了什么（方案/报价）
5. 客户什么反应（反馈/卡点）
6. 下一步是什么（承诺/动作）
7. 有没有数字、日期、决策

不要复述全文；用“事实 + 证据”。

---

## 3. 跨帖综合

### 3.1 时间线

按时间排，不要按帖子重要性排。每条：

```text
日期 | 事件 | 来源
```

### 3.2 关系图

- 客户方：品牌/业务部门/公关/采购/代理
- 我方：销售/策划/内容/商务
- 代理：服务哪些品牌、话语权

### 3.3 商机漏斗

```text
接触 → 需求确认 → 方案 → 报价 → 谈判 → 下单 → 执行 → 复购
```

标出当前阶段和卡点。

### 3.4 数字演变

- 预算
- 报价
- 折扣
- 投放量级
- 时间节点

同一指标多个版本时，列时间线，不取平均值。

### 3.5 矛盾与缺口

- 原文冲突：两个人说的数字不一样
- 时间变化：3 月说 63 万，6 月说预算 pending
- 信息缺口：没有明确预算出口、没有决策人、没有下一步时间

---

## 4. 三层反馈

### 事实层

```text
原文：客户表示预算只有 3.5–4 万，要求做两版报价。
证据：comment#1, 2024-05-14
```

### 判断层

```text
判断：这个量级更像“试水单”，不是品牌 campaign；决策权可能在代理/执行层。
置信度：中
依据：预算低于 5 万、客户要求两版报价、负责人强调 5 万以下先付款。
```

### 行动层

```text
建议：不要按大项目配置资源；用标准化轻量包 + 明确交付边界；
先确认预算出口和付款方式，再谈资源置换。
触发条件：客户确认 5 月 27 日节点。
```

---

## 5. 置信度

| 级别 | 含义 |
|---|---|
| high | 多个独立证据，时间/数字一致 |
| medium | 单一来源，或存在小冲突 |
| low | 推测、信息缺口大 |

判断层必须带置信度；事实层不需要。

---

## 6. 不要做的事

- 不要把“搜索命中”当“相关”
- 不要把“帖子最后回复”当“项目当前状态”
- 不要用一个帖子的结论覆盖另一个帖子
- 不要把代理的话当客户确认
- 不要编造预算、决策人、时间
- 不要把“没找到”说成“没有”

---

## 7. 报告里的“所以呢”

每篇直接相关帖子结尾加一句：

```text
所以呢：……
```

不超过两行，指向下一步或风险。

整篇报告结尾给：

- 3 条以内最重要的判断
- 3 条以内最建议的动作
- 3 条以内最需要确认的问题
